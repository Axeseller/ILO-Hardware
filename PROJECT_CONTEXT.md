Hardware rules:
- ESP32 logic is **3.3 V**. Never wire 5 V signals directly to GPIO pins.
- Always use a **series resistor (220-330 ohm)** with LEDs.
- The ESP32-S3 has built-in **Wi-Fi and Bluetooth LE**; no extra radio module is needed.
- Don't invent pin assignments. Before using a pin, check the specific board's pinout (some GPIOs are strapping pins, tied to flash/PSRAM, or the onboard LED/USB). If unsure, ask me.
- ESP32-S3 boards often have two USB ports (UART and native USB). If upload fails, try the other port or hold BOOT while plugging in.

## 4. Development environment

- **OS:** Fedora 43 (Linux), Guadalajara, Mexico.
- **Editor:** Cursor (VS Code fork; extensions come from Open VSX).
- **Build system:** **PlatformIO via the terminal** (PlatformIO Core CLI, installed with the official installer so it lives in `~/.platformio/penv`). The official PlatformIO VS Code extension is **not** the plan for now, since it isn't reliably available in Cursor.
- **Framework:** Arduino framework on ESP32-S3.
- **Language server:** `clangd` extension with a `compile_commands.json` generated by `pio run -t compiledb`, plus a `.clangd` file to strip GCC-only flags and `--query-driver` pointing at the Xtensa toolchain. Cursor's built-in C/C++ IntelliSense should be disabled for this workspace to avoid duplicate errors.
- **Serial permissions:** my user must be in the `dialout` group. The board appears as `/dev/ttyACM0` or `/dev/ttyUSB0`.

Common commands:

```bash
pio run                              # build
pio run -t upload                    # flash
pio device monitor                   # serial monitor (set monitor_speed in platformio.ini)
pio run -t compiledb                 # regenerate compile_commands.json for clangd
pio run -t clean                     # clean build
pio run -t upload && pio device monitor
```

Re-run `compiledb` after changing `platformio.ini` or adding libraries.

## 5. Repo conventions

- Source in `src/main.cpp` (not `.ino`), starting with `#include <Arduino.h>`.
- Config in `platformio.ini`; keep the environment name explicit and tell me when it changes (the `.clangd` path depends on it).
- Libraries go in `platformio.ini` via `lib_deps`, not copied into the repo, unless there's a reason.
- Add `.pio/` and `compile_commands.json` to `.gitignore`.
- Prefer small, readable modules over one giant `main.cpp` once the prototype grows (e.g. `led`, `ble`, `button`).
- Comment *why*, not just *what*, especially around pin choices and timing.
- Use named constants for pins and timings (no magic numbers).
